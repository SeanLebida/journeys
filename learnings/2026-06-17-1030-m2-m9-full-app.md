# M2–M9 — Content pipeline, four modes, offline, OTA, release prep

Completes the app: data model + accuracy gate, the Bible DB, all four interaction
modes, offline PWA, an OTA content channel, and store-release materials.

## What changed
- **M2 content (schema + gate + DB):** `src/content/schema.ts` (zod = single source of truth; TS
  types inferred, JSON Schema emitted), `scripts/build-content.ts` (the accuracy gate: zod validation,
  citation closure, neutrality invariants, FK + scripture-resolves-in-DB + geo-bbox + quiz + license +
  review-gate checks), Bible DB compiled with **sql.js** (KJV + ASV, 62k verses → `content.sqlite`).
  Seed content generated from the research workflow by `scripts/seed/generate.mjs` + hand-authored
  persons/artifacts/terms/lessons/quizzes. Hooks `useBundle`, `useBible`, `citations.tsx`.
- **M3 trace:** `src/map/route.ts` (pure haversine progress, unit-tested), `layers/trace.ts`,
  `useRouteAnimation.ts` (rAF, reduced-motion jump, fitBounds), `TraceMode` (picker, transport
  controls, live stop panel with scripture + citations + dispute notes).
- **M4 atlas:** `layers/atlas.ts` + `AtlasMode` (layer toggles, confidence filter, period slider,
  click-a-site detail).
- **M5 lessons / M6 quizzes:** `LessonMode` (step player driving the map camera), `QuizMode` +
  `useQuizStore` (mcq / true-false / order-stops / map-pin scoring, persisted best score).
- **M7 offline:** `vite-plugin-pwa` precaches the shell + bundle + 10 MB Bible DB + wasm (file-size cap
  raised); SW registered web-only.
- **M8 OTA:** `build-content` emits `manifest.json` (version + integrity); `content/*.extra.json` merge
  lets content extend without regenerating; `contentUpdate.ts` checks a configurable remote manifest;
  apostolic-traditions journey added (exercises the `legendary` tier + "other apostles" scope).
- **M9 release:** `CreditsView` (/about) with enforced attributions, `PRIVACY.md`, `docs/STORE.md`,
  app icon + manifest icons, version → 0.2.0 (bundle reads it), `build-content --release` gate.

## Why it mattered
- The gate makes "accuracy" mechanical and enforceable: a broken citation/ref/coordinate fails CI, and
  `--release` blocks shipping `high`-confidence claims that no scholar has signed off — matching the
  user's "+ human scholarly sign-off" choice without faking approval.
- zod-as-source avoids schema/type drift; sql.js avoids native compilation (the sandbox blocks
  postinstall scripts, so `better-sqlite3` was a non-starter).

## Gotchas / pitfalls
- **WEB → ASV substitution.** A clean single-file public-domain WEB JSON wasn't reliably fetchable;
  bibleapi's KJV+ASV are single-file, identical 66-book numbering, and ASV sidesteps WEB's trademark.
  KJV (the user's other pick) is retained.
- **Vite `base` './' breaks nested-route asset fetches** (`/trace/:id` resolves relatively); switched to
  `/`, which also serves correctly via Capacitor's local server.
- **sql.js wasm** must be served: `import wasm from 'sql.js/dist/sql-wasm.wasm?url'`.
- `@playwright/test` was missing from deps (only the browser binary was installed globally); the global
  `playwright` can't resolve the local config — run `./node_modules/.bin/playwright`.
- Vitest `toBe` uses `Object.is` → `-0 !== 0` (bit twice: graticule + route tests).
- Workbox default 2 MB file cap drops the 10 MB DB — raise `maximumFileSizeToCacheInBytes`.

## Verification
- `npm run build:content` (validates 58 sites / 6 journeys / 65 stops / 148 citations, compiles KJV+ASV)
  → green; `--release` correctly FAILS on 102 unreviewed high-confidence claims (gate proven).
- `npm run typecheck && npm run lint && npm test` → 28 unit tests green.
- `npm run build` → PWA precache 22 entries (~12.7 MB incl. Bible DB).
- `npx playwright test` → 6/6 E2E in real Chromium: home, journey list, **scripture from the sql.js DB**,
  quiz scoring, WebGL map mount, **offline reload via service worker**.
