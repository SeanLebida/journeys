# M0 — Project scaffold + platform abstraction

Implements milestone M0 of the approved plan:
an offline, cited, interactive atlas of the missionary journeys of Jesus and the apostles —
one React+Vite+TS codebase shipped as static web + iOS + Android (Capacitor), MapLibre maps.

## What changed
- **Build/config:** `package.json` (React 18.3, Vite 6, TS 5.7, Vitest 2, ESLint 9 flat config,
  Capacitor 6 CLI), `vite.config.ts` (`base:'./'`, Vitest jsdom), `tsconfig.json` (bundler
  resolution, strict, `@/*` alias), `eslint.config.js` (typescript-eslint + a guard rule that
  warns on hardcoded-coordinate literals in `src/` — facts must come from the content bundle),
  `capacitor.config.ts` (`webDir: dist`; note to strip live-reload before release), `.gitignore`,
  `index.html`, `.github/workflows/ci.yml` (typecheck/lint/test/build on Node 20).
- **App shell:** `src/main.tsx`, `src/App.tsx` (layout route mounting the persistent map once),
  `src/routes.tsx` (React Router; `createBrowserRouter` on web / `createHashRouter` on native;
  lazy-loaded mode screens), `src/map/MapProvider.tsx` (context holding the single MapLibre
  instance in a ref — placeholder surface until M1), 4 mode placeholders under `src/modes/*`,
  `HomeView`/`TabBar`/`SourcingDisclosure` components, an "ancient cartography × night sky"
  token system (`src/styles/{tokens,global}.css`).
- **State:** Zustand stores `useUiStore` (persisted prefs), `useJourneyStore` (transient
  animation state), `useDownloadStore` (persisted offline manifest); `persistAdapter.ts` bridges
  localStorage (web) ↔ `@capacitor/preferences` (native).
- **Platform abstraction:** `src/platform/{bridge,assets}.ts` — the single web-vs-native seam
  (`convertFileSrc` + fetch-as-blob, never base64; asset path registry for PMTiles/tiles/Bible DB/bundle).
- **Content groundwork:** `src/content/books.ts` (Protestant 66-book numbering + abbreviations),
  `src/content/scriptureRef.ts` (reference parser/formatter reused by the M2 validator) + unit tests;
  `scripts/build-content.ts` (M0 stub describing the full M2 accuracy gate).
- **i18n:** `react-i18next` initialized; English bundled; locale dimension reserved everywhere.

## Why it mattered
- Locks the architecture the research workflow + both adversarial critics converged on: one build,
  one persistent WebGL map, content/code separation, and a11y/i18n/offline designed in from M0 rather
  than retrofitted (the completeness critic's biggest warning).
- The scripture-ref parser and 66-book table are the foundation of the M2 "scripture integrity" check
  (every authored ref must resolve), so building + testing them now de-risks the accuracy gate.
- Platform seam isolated to `platform/assets.ts` so M1 map wiring and M7 offline work touch one file.

## Gotchas / pitfalls
- **React Router v6.28, not v7** (plan said v7). v6's `createBrowserRouter`/`createHashRouter` APIs are
  identical for our use and avoid the v7 package rename churn. Revisit if v7-only features are needed.
- Native uses **hash routing** — deep paths over the `capacitor://` origin blank-screen on reload otherwise.
- ESLint coordinate-guard is a `warn` (not `error`) so legitimate non-fact decimals don't block CI; revisit
  severity once content authoring starts in M2.
- `better-sqlite3` and native Capacitor platform packages are intentionally **deferred** to M2/M7 — they pull
  native builds (risky on the very new Node 26 host) and aren't needed for a green M0.

## Verification
- `npm install` then `npm run typecheck && npm run lint && npm test && npm run build` — all green
  (see the commit's CI run / local output). Tests: scripture-ref parser (8 cases) + HomeView shell
  (title, 4 mode links, sourcing disclosure).
- `npm run dev` serves the shell with the home view, tab bar, and all four placeholder mode routes.
- `npm run build:content` runs the M0 stub without error.
