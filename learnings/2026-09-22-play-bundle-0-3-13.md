# 0.3.13 signed bundle, versionCode 112

## What changed

- Built a signed release bundle for 0.3.13. `scripts/bump-android-version.mjs` set `versionCode` to 112, the git commit count, and that value is now in `android/app/build.gradle`.
- The bundle is `android/app/build/outputs/bundle/release/app-release.aab`, signed `META-INF/JOURNEYS.RSA`. Release notes were generated from the 0.3.13 changelog section (336 characters).

## Why it mattered

Play rejects a second upload of the same version code. The bump script proposes `max(commit count, current + 1)`. Leaving the file at 103 would make the next build emit 112 again after this bundle is uploaded.

## Gotchas / pitfalls

- This repo's GitHub Actions secrets list is empty, so `android-aab.yml` cannot sign a bundle or call the Play API. There is no Play service account JSON on this machine, and the local Chrome profile is not signed into Play Console. The upload is still a manual step in Play Console.
- The store listing is not inside the bundle. Paste `docs/STORE_LISTING.md` into Grow users > Store presence > Main store listing. The track this project documents is Internal testing. Closed testing is a separate release in the console.
- `android/release-notes/whatsnew-en-US` stays gitignored. `npm run android:release:notes` rewrites it from the first changelog section.

## Verification

- `npm run android:build:release` finished with `BUILD SUCCESSFUL`. `jarsigner` lists `META-INF/JOURNEYS.RSA` on the bundle.
- `versionName` is `0.3.13`. `versionCode` is `112`.
